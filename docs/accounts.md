# 账号、身份与权限 · v0.3

账号体系使用同源 Cookie 会话，玩家席位绑定账号。管理用户、管理内容和主持房间是不同的权限边界。

## 首次配置

在首次启动前设置 `.env`：

```dotenv
HEXBOUND_BOOTSTRAP_ADMIN_USERNAME=your-admin-name
HEXBOUND_BOOTSTRAP_ADMIN_PASSWORD=replace-with-your-own-long-password
HEXBOUND_ALLOW_REGISTRATION=1
HEXBOUND_SESSION_TTL_SECONDS=604800
```

请替换示例密码，不存在内置默认管理员密码。用户名为 3–32 个英文字母、数字、下划线、点或短横线，以字母或数字开头；大小写视为相同账号。密码为 10–128 个字符，支持长口令。部署到 HTTPS 入口后设置 `HEXBOUND_COOKIE_SECURE=1`；本地 HTTP 开发可不设置，服务会按请求协议判断。请勿在 HTTP 下强制 Secure Cookie，否则浏览器不能维持登录。

初始化只执行一次，不会在每次重启时覆盖管理员密码，也不会把同名普通用户升级为管理员；用户名被占用时会明确报错。创建成功后可以移除初始化密码环境变量。账号和会话随 SQLite 备份保留。未设置初始管理员时普通用户仍能注册和游玩，但没有用户自动成为管理员；应由部署者完成初始化。

访问 `/account.html`：注册或登录后可进入冒险桌、修改密码、退出当前会话或全部设备。管理员会看到用户管理和审计入口。

## 角色矩阵

| 操作 | 玩家 player | 创作者 creator | 管理员 admin |
| --- | --- | --- | --- |
| 浏览已发布摘要 | ✓ | ✓ | ✓ |
| 创建、加入及恢复自己的房间 | ✓ | ✓ | ✓ |
| 控制自己绑定的角色 | ✓ | ✓ | ✓ |
| 主持房间：开始、暂停、场景编辑 | 仅该房间房主 | 仅该房间房主 | 仅该房间房主 |
| 内容库草稿、编辑、发布、导入导出 | — | ✓ | ✓ |
| 用户查询、角色调整、启停、密码重置 | — | — | ✓ |
| 账号安全操作审计 | — | — | ✓ |

注册只能获得 player。客户端不能提交角色或指定拥有者来提升权限。工坊是部署内共享内容库，creator 可以管理整个内容库；当前没有每个内容条目的所有者 ACL 或多人审批。管理员身份不赋予冒领他人角色或绕过房主限制的权利。

## 用户管理

管理员可按用户名/显示名、角色和启用状态查询，并分页查看；修改使用账号版本检测并发冲突。角色改变、禁用和密码重置会撤销受影响账号现有会话。系统拒绝禁用或降级最后一个有效管理员。

密码重置由管理员指定临时密码，用户下次登录必须先改密，才可访问游戏和工坊。临时密码应通过可信渠道单独交付；服务不发送邮件，也不提供邮件找回。密码修改要求当前密码，成功后撤销所有旧会话，只为当前设备重新签发会话。

审计记录注册、登录失败/成功、退出、改密和管理员变更等账号安全操作，不记录密码、Cookie 或 CSRF token。该日志不等同完整游戏与内容管理行为审计。

## 会话与请求

会话是不透明的随机标识，数据库仅存会话标识哈希。浏览器通过 HttpOnly、SameSite=Lax Cookie 持有会话；前端不将其放入 localStorage。认证写请求需要 `/api/auth/me` 返回的 CSRF token，通过 `X-CSRF-Token` 请求头提交。登录/注册检查 Origin，并接受结构化 JSON；跨站请求拒绝。

服务端在每次请求查询最新账号、角色与会话；WebSocket 在推送前和连接轮询时复核，退出或禁用后最长约 2 秒的空闲轮询内断开，事件循环负载可能影响实际延迟。注册和登录有限流，密码派生在工作线程中执行。密码使用带随机盐的 scrypt；高成本派生限制并发，避免阻塞游戏事件循环。

会话默认有效期 7 天，可配置 300 秒至 30 天。当前没有 MFA、SSO、邮箱验证或分布式限流，仍要求单进程单实例部署。反向代理须正确传递原始 HTTPS 协议，并仅信任实际代理来源；不要无条件信任公网提交的 Forwarded 头。

## 老版本升级与席位认领

升级会自动为旧 members 表增加可为空的账号字段及唯一索引，保留原房间与内容。默认 `HEXBOUND_ALLOW_GUESTS=0`、`HEXBOUND_LEGACY_ADMIN_TOKEN=0`，不再允许匿名开团或共享密钥管理。

原设备的本地席位记录保留。先注册/登录，在首页选择“认领旧席位”；服务验证原成员凭证，原子地绑定账号。认领后旧凭证失效，后续可在任意设备登录，从“继续冒险”恢复。一账号在同一房间最多拥有一个席位；已绑定席位不能被其他账号认领。旧凭证丢失时不会仅凭邀请码转移角色。

如确需过渡期匿名游玩，可临时设置 `HEXBOUND_ALLOW_GUESTS=1`；共享管理密钥需同时显式设置 `HEXBOUND_LEGACY_ADMIN_TOKEN=1` 与 `HEXBOUND_ADMIN_TOKEN`。兼容模式只用于未绑定的旧身份，不会绕过已登录账号的权限或已绑定席位。迁移后关闭两个开关。

## 验证与依据

测试覆盖默认关闭旧身份、角色隔离、CSRF、密码与会话撤销、最后管理员保护、旧存档迁移以及六个独立账号联网游玩。测试命令与结果见 [验证记录](validation.md)。真实浏览器和生产安全测试仍需单独验收。

安全设计参考 [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) 与 [CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)，SameSite 与 CSRF token 同时使用。
