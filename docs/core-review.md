# 核心规则与跑团体验独立评估

评审日期：2026-10-23。范围：2014 SRD 5.1 的职业与法术目录、角色成长、独立战斗、DM 提案和持久角色的集成。本文先记录实现契约和验收门槛；进行中的实现不能视为已经通过验证。

## 产品覆盖声明

规则版本固定为 2014 SRD 5.1，不能混入 2024/5.2 的职业成长或施法规则。参考源：[Wizards SRD 5.1](https://media.wizards.com/2016/downloads/DND/SRD-OGL_V5.1.pdf)。完整目录和完整自动执行是不同交付：12 个核心职业、18 项技能、全 SRD 法术目录和 1–20 级成长应逐项列出；每个特性及法术分别显示“自动结算”“参考/人工裁定”或“不支持”。自动化标记必须来自实际处理器注册表，不得由名称匹配或 LLM 判断。

参考类法术仍应具有可检索的名称、等级、职业、施法时间、射程、成分、持续时间及规则描述。复杂变形、召唤、幻术、区域、反应、专注等未实现的效果必须明确注明，不得扣资源后输出一段叙述就宣称已执行。多职业、专长、种族背景、装备交互是否完整属于独立能力，不应被“全职业”隐含承诺。

## 初始结构中的集成风险

| 已读结构 | 风险 | 验收要求 |
| --- | --- | --- |

## 必须满足的权威与幂等契约

1. 角色创建与升级只接受选择项，不接受客户端的等级、XP、HP、熟练、法术位、资源或已解锁能力。一次升级最多一级，并要求 XP 阈值或服务端可信里程碑许可。房主不能替其他账号升级或修改持久角色。
2. 属性提升、技能/专精、子职、已知/准备法术等选择按职业和等级校验数量、唯一性和候选池。更高阶法术不能依靠直接提交 ID 学会；准备不能超出已知/法术书。CON 提升需要回溯历史等级的最大 HP 修正。
3. 单一持久角色不能同时在多个活跃房间独立消费资源；如采用房间副本，必须明确隔离且禁止无条件覆盖主角色。重连、换房、升级、重启不得凭空恢复所有消耗。
4. 战斗每个实例具有稳定 ID。胜利奖励依据服务端敌人快照和参与者产生，按角色与实例唯一记账。重复 command、重复结束、重新进入节点、崩溃后重放不得再获 XP。客户端或 LLM 不能指定奖励数额。
5. 休息具有明确恢复周期和完成语义。相同 command 重放不能再次治疗或返还资源；合法短休不应返还长休资源。界面应解释当前可恢复内容。用于演示的快速休息必须标为房规。
6. 行动先验证目标、归属、回合和资源，成功提交时才扣除；失败不得部分修改。法术目录可见不等于可施放；准备/已知、法术位、施法职业及自动化状态均需服务端复核。
7. DM 提案仅能引用合法的服务器命令/能力。过期状态、会话撤销、非提案主体确认、重复确认、修改提案 payload 均需拒绝或幂等返回；叙述不能直接修改战斗、角色或 XP。

## 用户验收路径

- 新用户可以理解地选择职业并完成一级角色；缺少选择时指出具体字段和允许数量，而非无解释的 422。
- 角色页展示本级能力、下一等级收益、XP 进度与资源；参考特性明确不自动执行。查看另一个队员只能看到约定公开信息。
- 开战与探索独立可用；战斗显示当前回合、合法目标、资源成本、实际骰子与判定。无效行动不消耗资源。
- 同一角色跨设备恢复保持资源一致；第七席被拒绝，离线角色不会产生额外奖励份额。
- 升级提交失败后保留表单；重复点击不会升两级；升级后新的角色能力真实影响服务器合法行动。
- 模型断线时确定性战斗仍能完成；人工自由模式与预设模式都可以进入、退出遭遇，结束后不丢失剧情进度。

## 独立集成测试计划

接口落地后，优先新增 `tests/test_core_integration.py`：跨账号角色读写拒绝；伪造派生字段拒绝；升级重试/并发去重；同角色多房间冲突；战斗奖励重试及重启去重；休息收据与恢复范围；不属于角色的法术/能力拒绝；无效目标不扣资源；DM 过期提案与重复确认；公开房间视图无私密角色字段。

当前阶段已完成既有结构审查，并与角色/战斗/目录/界面负责代理同步以上风险；新的核心接口尚未落盘时不编写依赖猜测接口的测试，也不宣称验证通过。

## 最终独立 API 复验

核心接口落盘后新增 `tests/test_core_integration.py`，独立执行：

```text
python -m pytest -q tests/test_core_integration.py
8 passed, 1 warning in 7.66s
```

测试使用真实注册 Cookie、CSRF 与 HTTP 路由；仅通过可信服务器存储夹具布置 XP、战斗濒死敌人和冒险完成状态，以避免把客户端授予数值当作合法接口。

| 验证 | 结果 |
| --- | --- |
| 他人角色不可读、不可编辑、不可绑定；伪造 XP/level 被拒绝 | 通过 |
| 同角色只能绑定一个活跃房间；完成后可复用，旧房间不能升级/休息/装备该角色 | 通过 |
| 升级前检查 XP；同命令重试只升一级，房间成长同步持久角色 | 通过 |
| 场景 XP 在重试与应用重启后不重复结算 | 通过 |
| 短休重试不重复扣生命骰、无生命骰时失败；当前房间长休冷却 | 通过 |
| 未拥有的法术/剧情卡被拒绝，失败不改变房间状态 | 通过 |
| 角色完成冒险后复用，长休冷却仍有效且失败不改资源 | 通过 |
| 击杀真实遭遇产生战斗奖励；重复命令与再次攻击不能重复获 XP | 通过 |

实际发现并修复：初版长休时间只存房间，复用角色进入新房会重置冷却。实施代理将角色时间与最近长休结束时间持久化，并在房间绑定/同步时继承；上述跨冒险用例已验证拒绝立即再次长休。房间广播已改为公开字段投影，角色绑定及同步会跳过已经迁入其他房间的旧角色副本。

仍须保留的产品边界：准备法术可在战斗外自由调整属于当前房规，应在 UI/说明中明确；角色详情接口现在提供完整角色卡，当前没有用户私密字段，未来新增私密笔记或账号元数据时必须收紧投影。此次未独立重跑所有职业/法术单元测试、六人浏览器测试、并发压力或所有高级特性组合；相应结果由负责代理及总体验证提供。复杂能力的参考状态不能据此升级为自动化支持。
