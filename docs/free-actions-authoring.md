# 环境对象与自由行动创作

在 `/studio.html` 打开剧本，进入节点编辑器的「环境对象」区。添加对象，填写名称、描述、标签、耐久与难度，再校验、保存并发布。右侧预览显示当前对象与非法字段提示，发布仍以服务器严格校验为准。新房间使用已发布快照；修改草稿不会改变正在进行的房间。

每个节点最多 20 个对象，ID 必须在节点内唯一，由英文字母或数字开头，其余只能是字母、数字、下划线或连字符，最长 64 字符。名称 1–80 字符，描述最多 1000 字符。HP 为整数 1–100，默认 10；DC 为整数 5–25，默认 12。标签不得重复，也不能自定义标签或脚本字段。

| 标签 | 作者应描述的事实 | 对应行动能力 |
| --- | --- | --- |
| `movable` | 能推动、倾倒或拿起的物件 | 推倒障碍、临时武器 |
| `cover` | 足以遮挡身体的障碍 | 搭建掩体、隐蔽 |
| `flammable` | 能燃烧的材质 | 点燃 |
| `fire` | 场景开始时已经燃烧的对象 | 可被熄灭的火源 |
| `searchable` | 可观察、翻查的具体物件 | 搜索 |
| `interactable` | 能操作的具体物件 | 切换操作状态 |
| `sand` | 现场实际存在的沙土 | 扬沙 |

例如海关铁柜可有 `movable,cover,interactable`，账册可有 `searchable,flammable`。可燃不代表正燃烧；只有 `fire` 提供初始燃烧状态。点燃另一个物件需要场景里已有仍存活的火源；不能凭空造火。推倒障碍、搭建掩体、隐蔽和搜索使用对象 DC，扬沙固定 DC 12。重要线索不要只放在可烧毁对象上：为失败与损毁保留正常的节点行动出口。对象描述不是执行指令，不应写“成功后获得 100 XP”或“运行脚本解锁大门”；奖励和节点推进仍由已注册规则与剧情图负责。

```json
{"id":"iron-cabinet","name":"海关铁柜","description":"倾倒在透镜旁的旧铁柜。","tags":["movable","cover","interactable"],"hp":30,"dc":12}
```

玩家在自由意图区描述动作，系统只提出当前对象、目标与已注册动作构成的合法方案。玩家确认后由服务器重新检查场景、资源与回合并掷骰。模型不能根据一句叙述临时生成不存在的铁柜、沙土、伤害或奖励。旧存档缺少 `objects` 时视为空；不从小说文本推断可执行对象。LLM 新剧本也必须通过同一对象结构校验；混合模式仅改写叙述，不修改对象集合。

环境是公开的抽象规则，而不是完整物理引擎。移动使用接战／撤远姿态，没有二维地图、精确碰撞或完整借机攻击。掩体提供当前实现的半身掩护；隐蔽、扬沙和燃烧采用界面方案中公开的房规。燃烧不是现实时间模拟：每个战斗回合结束，或每次战斗外确认自由行动推进 6 秒，燃烧对象每次损失 2 HP，直到熄灭或烧毁；搜索与交互只记录对象状态，不凭空生成战利品，也不直接替代主线节点行动。对象 HP、燃烧、倒塌、搜索与操作状态由服务器保存。实施前以当前方案显示的检定、难度、成本和限制为准。

扩展对象行为需要修改服务端动作注册表、输入校验、执行处理器并加入测试；仅在工坊中填写新标签、代码、公式或数值字段不能增加执行能力。复杂几何、材料燃烧速度、坍塌链式反应和任意即兴法术效果不在当前自动化范围内。
