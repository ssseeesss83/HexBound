# 模块化内容与冒险运行时

工作室管理技能、怪物和节点图剧本。编辑的是受约束的数据，不允许上传 Python、表达式求值或让模型执行自定义代码。发布前完成结构与引用验证，开团时将引用的已发布内容及版本复制到房间；此后修改原卡片不改变正在进行的冒险。

## 运行边界

`campaign.start_campaign(state, package)` 初始化独立内容运行时；`available_actions(state, member_id)` 生成当前合法动作；`apply_action(state, member_id, action_id, target_id)` 使用服务端卡片执行并返回事件。旧版预设冒险仍由 `rules.py` 执行。

房间状态的 `campaign.package` 是内部快照，包含剧本图、卡片和发布版本。不得直接发送到玩家客户端。公开场景只包含当前标题、正文、目标；动作仅公开可执行 ID、名称、目标名单和剩余次数，未来节点与分支路由不在公开场景中。

## 卡片效果

| 效果 | 使用地点 | 目标 | 脚本公式 |
|---|---|---|---|
| attack | 战斗 | 存活敌人 | d20 + 属性调整值 + 熟练 + bonus 对 AC；伤害骰 + 属性调整值 + bonus |
| heal | 战斗或探索 | 自己或存活队友，可救治倒地者 | 骰式 + bonus，截断到最大 HP；不能复活 |
| check | 节点挑战 | 场景 | d20 + 属性调整值 + bonus 对卡片 DC，按成功/失败路由 |
| defend | 战斗 | 自己 | 下一次自身回合开始前，来袭攻击劣势 |

自定义技能是本游戏受限卡片系统，不代表完整官方职业或法术。`uses` 是每角色整场冒险次数；null 表示不限。失败的合法攻击或检定也消耗次数。非法目标、非当前回合、已用动作、未配置技能均在掷骰和扣资源前拒绝。技能不会自动因换节点恢复。

`EFFECT_HANDLERS` 将效果名映射到独立 Python 处理器，`EFFECT_TARGETS` 定义合法目标。新增效果需要增加 schema 枚举、服务端处理器、目标限制和规则测试；API 层无需增加新端点，仍提交 `skill:<id>`。发布端必须校验 schema 暴露的效果存在对应处理器，不能只扩展编辑表单。

战斗动作 ID 为 `skill:<卡片ID>`；基础武器攻击、闪避、结束回合始终由脚本提供。多个敌人必须明确选择存活目标，单敌人可自动选中。所有敌人使用独立实例 ID，即使同一怪物卡出现多次也不会共享生命。

## 节点图

节点包含正文、目标、动作与遭遇。没有 `skill_id` 的动作直接进入 `next_node_id`，由房主代表队伍执行；即使房主角色倒地或死亡，只要有清醒同伴也能推进。带技能的节点动作仅支持 `check`，清醒角色可执行；必须同时指定成功与失败路由，不可混用 `next_node_id`。

进入有怪物的节点先执行战斗，胜利后才开放节点动作。重复访问已经清理的节点不会重生怪物。结局节点必须没有动作和怪物，进入即结束冒险。发布校验应要求非结局节点有出路，并避免所有出路都依赖可耗尽技能；推荐保留一个无骰子的退路。

## 输入模式与权威规则

guided 展示作者预设行动，freeform 接收自由描述并保留合法动作，assisted 由模型建议行动后等待玩家确认。它们共享完全相同的服务端校验、骰子、资源与状态变化。模型建议只能引用当前合法 ID，不得直接提供数字或状态补丁。

## 首版明确限制

不支持代码插件、叠加持续状态、召唤、法术位、范围模板、完整反应链或网格移动。怪物卡目前配置属性、先攻和单次基础攻击，不支持技能组合或行为树；防御统一为闪避效果。死亡豁免采用旧运行时的简化时序：倒地角色点击结束回合触发；自然20恢复1HP但该轮结束。胜利后存活倒地角色自动稳定伤势属于公开房规。未来扩展新 effect 必须同时补充 schema、发布校验、运行时和测试，不能只在表单添加选项。
