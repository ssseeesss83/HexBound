# 行动计划接入记录

## P04c2a：现有能力的只读计划基础

`backend/action_plans.py` 尚未连接 HTTP / UI 执行入口，只预览当前 prototype-2014-v0.6 实际支持的武器攻击、法术、职业能力与结束专注。剧情节点动作、旧式角色、自由动作配方仍由后续统一管线接入；不把本批记作 A15 全部通过。

计划绑定房间、角色、场景实例、成员 epoch、规则包、结算配置、计划 schema、状态指纹与 120 秒到期时刻。预览及确认前重查均只读，不调用执行器再回滚，不掷游戏骰点，不扣费或推进回合。重查通过保留原计划 ID 和到期时刻。

- 自动选择后冻结真实法术位环级与来源，未指定来源可选择 pact；显式来源必须可用。戏法不消耗法术位。
- 目标按当前白名单、实际升环目标上限和唯一性核验；单目标与目标列表冲突拒绝。
- 资源列出法术位或职业资源点数；Smite 显式 `when=on_hit`，不把条件费用写成必然扣除。
- 动作预算区分首次攻击开始攻击动作并取得攻击额度、后续攻击只用剩余额度、动作 / 附赠动作。探索没有虚构战斗动作预算。
- 圣疗冻结实际投入，奥术回想 / 灵活施法冻结所选恢复位及当前原型限制；结束 / 替换专注单独列出。
- 未知结算配置、不可执行 / 无归属能力、非法类型、额外机械字段及不合法目标拒绝。确认重新检查身份、状态、资源、目标、范围、源数据版本和时效。

这层依照已有原型执行行为，不修正其房规。例如抽象近战距离、预选 Smite、灵活施法只恢复已有空位、简化范围等仍需 P08–P10 按完整 2014 规则替换。角色构筑合法性由构筑层验证；处理器测试中的隔离资源样本不证明完整角色已签收。

下一步：接入服务器冻结提案与双入口，确认只发送提案 ID，成功回执、骰点和资源同事务保存。新的 `action` 请求不能保留直接结算旁路；旧成功命令回放必须保持。挑战尝试账本单独按挑战及相关事实设计，不能直接使用这里的宽状态指纹作为重试资格。


## P04c2b：服务器冻结提案接入

新增 `capability_propose` 接收已选能力 / 目标 / 合法选项，生成服务器提案，确认仍只用 `director_resolve` 的 proposal ID。模型 / 本地自由描述通过 `capability` 决策引用同一可执行目录并使用同一 prepare / revalidate；本地只有一个明确合法目标时可识别攻击，否则要求明确目标。两种意图源单独保留，执行计划同构。

HTTP 不接受客户端提交的计划、代价或效果；公开计划通过白名单移除内部绑定和指纹。确认重新检查时效与状态后才调用既有处理器，扣费、骰点、消费提案和命令回执仍由原房间事务持久化。普通聊天不作废计划；成功回执在任何重新规划前回放。计划字段不能因为重新验证而延长生命期。

数据库 schema 11 保护持久化的新 capability 决策 / 计划；升级前备份、原存档不改写，当前计划随完整备份恢复，旧 schema 10 程序在任何写入前拒绝读取。ActionIntent 能力选项使用严格模型，不接收自定义数值效果。

**当前仍保留旧 `action` 直接执行与原菜单行为，待 P04c2c 统一所有必要动作后关闭。** 本批是服务端接入，不是唯一管线验收；也不升级原型处理器的严格规则支持状态。

## P04c2c1：冻结剧情行动计划

剧情选项、旧角色攻击、闪避、药水和发布剧本技能接入同一只读计划器，并冻结处理器家族、次数、目标与动作预算。节点检定的全部可能目的地先预检，公开计划不泄露未来节点。已验证的队伍指挥选项允许倒地领队提交，不能用该权限施法或进行角色动作。

计划 schema 升为 2；旧计划在公开投影中显示过期，并在确认时要求重选。仍兼容旧计划的公共显示字段，恢复不自动执行。旧 action 与原 UI 尚未切换，后续关闭旁路；当前模型能力目录暂不增加全部剧情选项。

## P04c2c2：关闭旧行动直接执行旁路

新 action 请求在历史成功回执检查后转入 capability_propose；不再存在能力直接执行分支。结束回合使用独立 end_turn 控制，action_id=end_turn 拒绝。界面选项、药水与施法选择均请求计划，审核卡展示后才可明确确认；多目标逐项列出。能力确认后按已确认结果叙述，转场后播报当前场景。

规划前的世界占用冲突保留 409 语义，聊天与读取继续可用。原成功 action 回执直接回放，不生成新提案或扣费。三次即兴检定限制尚待 P04c3，完整规则与反应窗口仍依赖 P08–P10。
