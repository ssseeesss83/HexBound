# 行动计划接入记录

## P04c2a：现有能力的只读计划基础

`backend/action_plans.py` 尚未连接 HTTP / UI 执行入口，只预览当前 prototype-2014-v0.6 实际支持的武器攻击、法术、职业能力与结束专注。剧情节点动作、旧式角色、自由动作配方仍由后续统一管线接入；不把本批记作 A15 全部通过。

计划绑定房间、角色、场景实例、成员 epoch、规则包、结算配置、计划 schema、状态指纹与 120 秒到期时刻。预览及确认前重查均只读，不调用执行器再回滚，不掷游戏骰点，不扣费或推进回合。重查通过保留原计划 ID 和到期时刻。

- 自动选择后冻结真实法术位环级与来源，未指定来源可选择 pact；显式来源必须可用。戏法不消耗法术位。
- 目标按当前白名单、实际升环目标上限和唯一性核验；单目标与目标列表冲突拒绝。
- 资源列出法术位或职业资源点数；Smite 显式 `when=on_hit`，不把条件费用写成必然扣除。
- 动作预算区分首次攻击开始攻击动作并取得攻击额度、后续攻击只用剩余额度、动作 / 附赠动作。探索没有虚构战斗动作预算。
- 圣疗冻结实际投入，奥术回想 / 灵活施法冻结所选恢复位及当前原型限制；结束 / 替换专注单独列出。
- 未知结算配置、不可执行 / 无归属能力、非法类型、额外机械字段及不合法目标拒绝。确认重新检查身份、状态、资源、目标、范围、源数据版本和时效。

这层依照已有原型执行行为，不修正其房规。例如抽象近战距离、预选 Smite、灵活施法只恢复已有空位、简化范围等仍需 P08–P10 按完整 2014 规则替换。角色构筑合法性由构筑层验证；处理器测试中的隔离资源样本不证明完整角色已签收。

下一步：接入服务器冻结提案与双入口，确认只发送提案 ID，成功回执、骰点和资源同事务保存。新的 `action` 请求不能保留直接结算旁路；旧成功命令回放必须保持。挑战尝试账本单独按挑战及相关事实设计，不能直接使用这里的宽状态指纹作为重试资格。
