# Hexbound · 缚骰 — 界面与体验设计

状态：实施前设计稿。产品目标是让 1–6 名玩家围坐在同一张虚拟冒险桌边；画面围绕故事与行动组织，规则账本始终可核验。

## 1. 视觉方向：午夜航海日志

一张暗色桌面，一页被温暖灯光照亮的冒险记录，以及一枚轮廓鲜明的二十面骰。采用午夜墨黑、旧纸白与克制的黄铜色；玉绿色只代表可行动或已连接状态。不要套用后台管理平台的卡片矩阵，不使用大面积紫色渐变、无意义统计图或持续发光边框。

品牌：英文 `HEXBOUND`，中文 `缚骰`。副标题“命运有据，故事无界”。图形语言为六边形、细直线、断续航线及章节序号；d20 线稿作为主视觉，使用 SVG/CSS 构建以保持清晰。品牌字标字距约 `.18em`。中文正文使用系统字体，章节标题允许宋体回退，呈现阅读质感。

```css
:root {
  --ink: #101719;
  --panel: #182124;
  --panel-raised: #202b2e;
  --paper: #efe9dc;
  --muted: #adb7b7;
  --brass: #d4b77c;
  --jade: #a5d9b8;
  --danger: #f3a6a0;
  --line: #354246;
  --focus: #d4b77c;
  --radius: 12px;
  --space: 8px;
}
```

正文 16px / 1.8，辅助文本最低 12px / 1.5。标题使用 `clamp(32px, 5vw, 72px)`。主要交互高度至少 44px；按钮采用纸色填充与墨色文字，次级操作采用边框，选项保持明确可点击性。数字与掷骰公式使用等宽字体。色彩必须辅以文字或图形识别状态。

## 2. 进入冒险

首屏左侧为品牌、两句定位与清晰的“创建冒险”“加入房间”；右侧为大幅 d20 线稿与六席星图，席位数直接解释“1–6 位冒险者 + AI 主持人”。下方用紧凑三列说明：故事模式、真实掷骰、共同存档。避免使用不能真实操作的演示房间列表。

创建流程使用一张短表单：冒险名 → 昵称与预设角色 → 模式（预设剧本 / 自由生成 / 混合冒险）→ 主题与基调。选项卡包含一句差异说明。预设剧本明确预计时长、主题、适合人数。LLM 未配置时，说明当前可使用本地演示主持，不能把模板文本伪装成模型输出。

加入流程：输入邀请码、昵称、角色。房间已满、邀请码无效、角色冲突分别给出就地提示。成功加入后保持身份令牌，刷新恢复同一席位；令牌仅储存在当前设备，不放入可分享链接。房主可复制只含邀请码的邀请文本。

## 3. 桌面冒险桌

顶部高度约 72px：左为小型字标，中央为冒险名和章节，右侧为连接状态、邀请码、设置。房间信息保持窄，不侵占叙事。

主区域采用三栏：

| 区域 | 宽度 | 内容 |
|---|---:|---|
| 同行者 | 220–250px | 六席队伍、头像首字、角色名、职业、生命值、在线/离线、当前回合 |
| 冒险日志 | 弹性，正文最大 760px | 章节标题、DM 叙事、玩家行动、结构化掷骰结果、底部行动输入 |
| 场景与规则 | 280–320px | 场景名、当前目标、敌人、角色详情、最近一次规则判定 |

各栏用细线分隔，不给每一行套卡片。DM 内容采用宽松文章段落；玩家行动以小头像与发言人行署名。规则事件是低高度票据：`敏捷检定 · 14 + 2 = 16 · DC 13 · 成功`。点击可展开骰子原始值、修正来源、优势/劣势与事件编号。DM 叙事和权威规则结果视觉上分开。

战斗中在日志上方出现紧凑先攻轨道；当前角色高亮并显示“轮到你行动”。敌方生命值与动作根据游戏设计公开范围呈现。回合结束按钮与攻击操作相邻。非当前回合玩家仍可聊天，但不可触发战斗规则变更。

底部行动栏固定在中栏：主输入“你准备做什么？”；下方显示当前身份、发送操作，旁边提供实际支持的快捷动作（检定、攻击、休息、结束回合）。快捷动作打开包含合法目标与属性的紧凑表单。自由文本不暗示能够修改生命、物品或判定结果。检定待确认时，原输入下方出现请求，呈现属性、原因与“一次掷骰”按钮。

## 4. 反馈与异常

| 状态 | 呈现与恢复 |
|---|---|
| 连接中 | 顶部圆点 + “连接中”；保留已读日志 |
| 断线 | 琥珀提示“连接中断，正在重连”；写操作禁用，草稿保留 |
| 等待 DM | 日志内小型三点动效 + “主持人正在组织故事”；不伪造 token 流 |
| LLM 失败 | 明确失败条目与重试；已完成掷骰不重掷 |
| 发送失败 | 保留输入，给出可重试提示；避免静默吞错 |
| 回合冲突 | 指示最新当前角色并同步；不显示虚假成功 |
| 房间满员 | “六个席位已满”，允许更换房间码 |
| 玩家离线 | 席位保留并标注离线；重新加入恢复角色 |
| 存档成功 | 安静状态文字“已保存”，不重复弹 toast |

输入发送时禁用同一提交，服务端仍必须幂等处理。新消息出现时，仅当用户在底部自动滚动；向上阅读时显示“新记录”按钮。掷骰动画最长 500ms，展示的是已经由服务端确定的结果。

## 5. 移动端与无障碍

宽度 1100px 以下，右栏收进“场景”抽屉。760px 以下，叙事占满宽度，队伍收成顶部六枚头像；底部使用“故事 / 队伍 / 场景”三标签切换。行动输入置于安全区域之上，避免软键盘遮挡。角色详情与设置使用全屏对话框。

所有操作可键盘到达，焦点清晰可见；对话框设标题、焦点捕获和 Escape 关闭。表单使用真实 label。重要错误用 `role=alert`，聊天新增内容用温和的 `aria-live`；不对整个历史反复播报。支持 `prefers-reduced-motion`，关闭打字、骰子旋转及背景漂移。文字对比度目标 WCAG AA；生命值同时显示数字。

## 6. 实施验收

- 首屏一眼可辨识建立/加入两个入口，中文界面完整。
- 两个浏览器身份可进入同一房间，看到相同叙事与规则事件。
- 六席上限、连接、LLM 状态、行动成功/失败均真实反映后端。
- 桌面 1440px、平板 900px、手机 390px 不产生横向溢出。
- 使用真实首个冒险内容检查排版，而不是 lorem ipsum。
- 不用静态假按钮、假在线人数或预填聊天冒充真实功能。

后续增强：暗/明阅读切换、角色肖像上传、可选环境音、地图及空间战术界面。第一版优先把房间、故事、检定和战斗闭环做实。
