# v0.4 核心玩法与规则边界

本说明对应实际实现：2014 / SRD 5.1、单职业、最多六位玩家、服务端权威结算。完整规则资料、角色已经拥有的能力、当前可执行的动作是三种不同集合；界面不能把可查阅内容全部显示成角色已经学会的技能。

## 1. 从账号到第一场冒险

1. 在 `/account.html` 注册并登录。普通账号用于游戏；创作者和管理员另外拥有内容工坊权限。
2. 首页打开“我的角色”，选职业并命名。初始采用标准数组固定分配、合法职业技能和可用法术默认项；需要更细的选择时通过角色创建接口提供受校验的 `choices`。
3. 创建房间或输入朋友的邀请码，选择新角色或自己的持久角色。一个人物同时只绑定一个有效冒险，不能并行复制成两份独立资源池。
4. 房主开始，所有人看到同一场景和时间线；每个人只能执行自己的角色动作。返回首页不会删除席位。
5. 完成目标获得脚本奖励。战斗外打开“完整人物卡”，在满足资格后进行升级、准备法术或休息。

已绑定人物的成长与资源通过房间事务写回人物库。旧房间不会覆盖已经带入另一场冒险的人物状态。账号登录可跨设备恢复席位；旧匿名角色须使用原成员凭证认领。

## 2. 人物卡读法

| 区域 | 信息与作用 |
| --- | --- |
| 概览 | 职业、等级、XP、子职业、六属性、HP、AC、武器与生命骰 |
| 技能与豁免 | 全部18技能、熟练／专精标记与最终调整值；六种豁免 |
| 职业资源 | 当前／上限、短休或长休恢复方式、能否自动执行 |
| 法术 | 戏法、已知法术、准备法术、法术书、永远准备项、法术位与契约位 |
| 职业特性 | 到当前等级真正获得的职业／子职业特性；复杂效果明确标记参考 |
| 成长 | 下一等级、XP或里程碑资格、本级HP与选择要求 |

目录中的替代选项不会全部授予角色，例如十种龙族血脉候选并不是十项同时获得的特性。剧情卡片也不会因为属于场景库就自动成为所有人的个人能力。

标准数组为 15、14、13、12、10、8，按职业固定分配。当前不叠加未实现的种族／背景收益，没有完整种族、背景、专长、多职业或工具专精构建器；也没有让客户端直接指定属性总值、等级、HP或熟练加值的入口。

## 3. 1–20级成长

每次只升一级。XP使用SRD角色升级阈值；房间也可选里程碑模式，资格来自脚本记录的场景目标。重复命令和重复领取同一奖励不会再次发奖。场景奖励是原创冒险的成长安排，不冒充官方怪物XP。

升级预览显示需要处理的选择：

- **子职业**：在相应职业的获得等级选择，不能提前选、跳过或改成另一个职业的子职业。SRD开放目录每职业一个子职业。
- **属性提升**：本级获得时分配恰好2点，单项不超过20；战士和游荡者的额外提升等级独立处理。野蛮人20级的职业特性是另行计算的规则收益。
- **技能专精**：只能选已有熟练技能，保留旧专精；不能通过升级重置初始技能。逸闻学院的额外技能具有独立校验。
- **法术选择**：戏法／已知／法术书使用完整目标列表。已经学会的戏法不能随意重选；常规已知法术职业每次升级至多替换一个旧法术。法师保留原书并每级新增两项合法法术。
- **高阶选择**：魔法奥秘可跨职业选择并计入角色的已知法术；玄奥秘法按获得等级单独选择，不能随时替换。

生命采用固定平均值，不由客户端或模型掷骰。体质调整值上升时，补算所有已获得等级的生命收益。升级增加的最大生命与当前生命相应增加，原有伤势差额保留；倒地角色不会借升级自动苏醒。升级不会把已经消耗的法术位或职业次数填满，只获得新增加的容量。

`characters.level_up()` 是纯角色运算；账号归属、战斗状态、版本冲突和里程碑扣除在应用事务中验证。前端传的是选项，不是计算完成的人物卡。

## 4. 施法与能力归属

法术目录本地收录319项完整SRD记录，包含原文、等级、职业、施法时间、射程、材料、持续时间、专注、仪式与升环信息。运行不依赖外部API。

人物卡只展示该人物的戏法、已知法术、准备项、法术书及玄奥秘法；实际施放还要通过处理器、动作、目标和资源校验。

| 标记 | 含义 |
| --- | --- |
| `automated` | 当前实现可以脚本执行所登记的效果 |
| `assisted` | 主要数值能执行，空间或附加效果有明确的人工／抽象裁定说明 |
| `reference` | 已收录完整规则，尚没有可安全执行的处理器；不会仅凭描述施放 |

当前法术处理器覆盖攻击、豁免伤害、治疗、稳定伤势、临时生命、祝福、防护与标记等明确配方。火球术等范围效果采用“选定合法目标”的抽象遭遇房规，不模拟网格几何、遮挡或友伤。未实现的召唤、许愿、复杂对象变化或高价材料消费不会交给语言模型编造。

普通法术位与邪术师契约位分开存储。施放验证角色能否使用该法术、选择的位是否存在、目标是否有效、当前动作预算和次数是否足够；校验失败不能扣费。正在专注的效果具有归属，受到伤害会进行相应专注检定；新专注不能与旧专注任意叠加。

“准备法术”只修改准备列表，不是无成本重置已知法术、戏法或法术书。当前采用公开房规：可在战斗外调整准备列表，无需等待长休；不允许从其他职业挑选未获得的法术。仪式资格会显示在人物卡；只有实际实现仪式处理的动作才可使用，不能把目录的仪式标记理解为任意法术免费施放。

## 5. 战斗操作

进入遭遇后界面切换到战斗视图：队伍状态、先攻条、敌方卡片、行动面板和规则日志。点击目标，再选武器、职业能力、法术或装备的剧情卡片；施法确认框显示法术位和目标数量。

服务端负责先攻与回合、动作和附赠动作、额外攻击、命中和伤害、暴击、优势／劣势、职业资源与已实现状态。普通检定的自然1/20不自动成败；攻击则使用自己的自然1/20规则。暴击翻倍伤害骰，不把固定修正翻倍。

可执行职业核心包括狂暴、诗人激励、回气、动作如潮、圣疗、神圣惩击、气相关动作、奥术回想和灵活施法。**其他特性即使已经获得，也可能只提供规则参考。** 行动菜单会显示不满足条件的原因，而不是让玩家猜测按钮为什么无效。

未实现完整机会攻击、反应链、网格移动、距离、掩护、召唤物管理和所有状态交互。反应资源展示不表示所有反应法术都已实现。

倒地者在自己的回合点击结束回合进行死亡豁免；自然20恢复1HP但本轮结束。战斗胜利后自动稳定尚未死亡的倒地队友。这是当前明确的简化时序／稳定房规，不能称为完全还原SRD。死亡角色不能通过治疗药水或休息复活。

## 6. 短休、长休与资源

短休推进1小时，可选择花费剩余生命骰恢复生命，并恢复标为短休充能的资源和契约法术位。生命骰由服务器掷出，每枚加体质调整值，治疗不低于0。默认花费0枚，不能凭请求指定骰面。

长休由房主发起，推进8小时；游戏时间24小时内只能受益一次，冷却与时间随角色跨冒险保留。恢复生命与相应职业资源／法术位，恢复最多等级一半的生命骰（向下取整，至少1）。角色开始长休时须存活且至少1HP；应先救治倒地队友。重复休息不会获得超出资源上限的次数。

游戏时间与休息许可是本作的服务器规则，不与现实在线时长等同。当前没有完整食物、营地安全、睡眠中断与旅行生存模拟。

旧四原型存档会迁移到现代人物数据，其中守灯人映射牧师、行脚学者映射法师。迁移保留原属性、HP、伤势与护甲，不重复赠送生命或恢复已经记录的资源。

## 7. DM自由行动提案

在输入框选择“向 DM 提出行动”，描述目标和手段，例如“我检查石壁上的划痕，寻找机关”。系统保留正常场景行动，不要求玩家把自然语言写成命令。

模型只能提出受约束的三种结构：对话、技能检定或允许的遭遇。检定引用18技能之一和受限难度；角色技能加值来自人物卡，骰子来自服务端。提案可以关联合法场景挑战，不能越权选择任意未来节点。

提案保存在服务器。玩家确认时只发送提案ID；系统重新验证房间状态和提案时效，再结算骰子、资源或路由。角色死亡、回合变化或场景推进使原提案不再适用时，必须重新提出。模型输出的任意HP、伤害、等级、经验和装备并不是状态补丁。

这个机制扩展表达方式，而不是宣称开放世界的所有自然语言行为都已实现。模型不可用时，本地场景行动仍能完成预设冒险。

## 8. 工坊内容与职业规则的区别

工坊的技能卡是受约束的自定义内容：攻击、治疗、检定、防御四种效果。职业法术和职业特性来自角色成长与规则目录，不等同于作者随手给全队添加的卡片。

检定卡可指定 `proficiency_skill`，脚本读取该角色的熟练／专精加值；不指定时执行纯属性检定。怪兽卡的 `xp` 决定击败奖励。

当前人物可以装备剧情提供的个人卡片；重新装备不恢复已消耗次数。节点检定留在场景层。剧情本的发布版本和依赖在开团时冻结，编辑源内容不会改变房间中的快照。

扩展一个新效果需要同步修改Schema、处理器、合法目标检查、资源规则和测试。只添加文字描述或前端表单不会产生可执行规则。
