# 预设剧本的即兴导演

> 本文记录当前提案与尝试资格边界，实施进度见 [任务记录](implementation/progress.md)。动态图、续写和调度目标见 [D1.0 重新设计](redesign/README.md)，尚不能作为已实现能力使用。

预设剧本仍提供事实、挑战、关键节点与结局，但玩家可以描述自己的行动方案。导演将自然语言转换为可审查的提案，玩家确认后由脚本结算；模型回应本身不消耗资源、不自动掷骰。

## 三种提案

| 提案 | 模型决定 | 脚本决定 |
| --- | --- | --- |
| NPC／环境回应 | 对白、态度与当前环境的叙述 | 只记录叙事，不授予物品、经验或新能力 |
| 替代解法 | 对当前挑战提出另一种方式，选择 18 技能中的一种 | 读取角色技能加值、原挑战 DC、剩余次数及原成功／失败路由，实际掷骰 |
| 额外遭遇 | 从当前房间已经冻结的已发布怪物目录选一个怪物 | 房主确认后启动战斗；每场景最多一次，不因胜利自动完成主线挑战 |

例如：作者的挑战是“调查门框”，玩家可以提出“从窗外观察同类机关”。导演可建议察觉检定，脚本沿用作者设置的 DC 及分支。换一种解题方式不会给模型开放修改 DC、血量、物品、法术位、经验或剧情图的权限。

当前检定必须绑定已登记的作者挑战；物件搜索使用注册配方。未知目标先澄清，P06 的生成挑战注册尚待接入。没有按角色 / 场景计算的三次即兴检定额度；旧计数仅保留作历史数据，不授予或限制新行动。战斗中的武器、法术和能力选择与自由描述均先生成服务器计划，确认后由已支持的规则处理器结算。

作者挑战与搜索共享房间权威尝试账本。地点、目标、问题与相关证据决定资格，换措辞、技能、队员、分合队或休息不会重掷同一问题。当前注册挑战按一次证据结算，成功不会重复推进或奖励；确实可重复且有规则代价的新类型需另行登记、接费用处理器。旧布尔“已尝试”只迁移为结果未知的消费标记，不编造成功、骰点或知识。

## 可见信息与记忆

模型只获得当前场景、当前合法挑战摘要、当前冻结怪物摘要、最近公开事件与有限叙事记忆，不接收整张剧情图、未来节点正文、成功／失败目标 ID 或隐藏结局。记忆保存已确认的对话或检定叙事，最多 32 项；它是叙事上下文，不能被当作修改规则的指令。

玩家看到提案名称、技能、DC、代价与成功／失败后果；没有任何规则状态会在确认前改变。模型失败或格式不合法时，提供本地提案，原剧情按钮保持可用。LLM 生成的叙事质量仍需真实模型与跑团体验验收。

## 服务端契约

- `await director.propose(dm, state, member_id, intent, policy="balanced")` 返回 `{proposal, source, text}`，不改变房间。
- 应用将完整提案保存在 `state.director.proposals[member_id]`，仅通过 `public_proposal()` 返回可见字段。
- 客户端确认时只提交 `proposal_id`。应用鉴权并检查命令版本、幂等回执，再从服务端存档取出该成员的提案传给 `resolve()`。
- `resolve()` 检查角色、场景、游戏状态指纹和已消费记录；聊天和版本号变化不改变指纹，角色资源、场景、剧情标志或战斗变化会使提案失效。
- 结算事件、已消费提案和房间变更必须在同一次保存中提交。失败时丢弃该次内存状态，不保存部分修改。
- 额外遭遇标记 `combat.director_encounter`，胜利不自动置主线 `scene_resolved` 或 `campaign.cleared`。遭遇限次是服务器状态，不能由模型重置。

暂不允许模型编辑剧情图、生成即时怪物属性或修改角色能力。复杂自由世界仍需要由内容作者配置可用挑战和怪物；导演扩展的是行动解释与场景应对，核心进度由服务器和作者约束。
