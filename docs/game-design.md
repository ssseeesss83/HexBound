# HEXBOUND · 玩法设计

设计状态：实施前方案。功能是否完成以 README 和测试为准。

## 1. 产品承诺

1–6 名玩家围坐同一张在线桌，AI 扮演 DM；每个决定都有可追溯的规则结果，每次失败都能继续故事。单人也能开始，不需要凑齐队伍。首版定位为 **基于 SRD 5.1 的 5e 核心规则子集**，不是完整 D&D 模拟器。

叙事自由不等于数值自由：玩家描述意图，服务器选择已注册动作并校验，规则引擎结算，DM 最后描述结果。LLM 无权直接修改生命、背包、法术位、先攻、骰子结果或任务完成状态。

## 2. 三种模式

| 模式 | 内容来源 | 约束 | 适合 |
|---|---|---|---|
| 预设冒险 | 原创场景图、NPC、线索、遭遇、结局 | 关键事实和通关条件固定；AI 只丰富对白与表现 | 第一次跑团、稳定通关 |
| 自由生成 | LLM 生成结构化冒险草案 | 服务端验证节点、合法 DC、敌人模板、奖励后锁定；非法内容拒收 | 重玩与即兴冒险 |
| 混合模式 | 预设主线 + LLM 支线与 NPC 对话 | 主线事实不可改写，支线只能使用已允许规则 | 长期团与探索 |

无 API Key 时提供明确标注的本地演示 DM，预设冒险仍可完整体验。自由生成在无模型时明确不可用，不用同一固定剧情冒充生成。

## 3. 首个原创冒险：雾港最后一盏灯

预计 30–60 分钟。队伍受雾港守夜人委托，重燃失联灯塔。潮水将到，灯塔却向海里投下影子。

| 场景 | 可玩选择 | 脚本事实与推进 |
|---|---|---|
| 雨夜码头 | 询问摆渡人、检查脚印、帮助搬运 | 三种入口线索指向海关仓库；失败仍得线索，但增加警戒 |
| 废弃海关 | 撬锁、说服看守、沿侧墙潜入 | 成功拿到透镜；失败进入可逃离的守卫遭遇 |
| 盐水阶梯 | 解读铭文、修复绞盘、绕行潮洞 | 正确调查揭示灯塔守望者被困；路径改变资源消耗 |
| 灯塔顶层 | 修灯、谈判释放守望者、攻击盐壳守卫 | 持有透镜可修灯；已找到誓言可谈判；战斗是第三种路线 |
| 黎明尾声 | 选择守护、带走或交还灯芯 | 依据服务器记录的线索、行为和存活状态生成结局 |

每条必需线索至少两条获取路径。调查失败不得永久锁死主线；重复同一调查不无限刷骰，场景状态变化后才能重试。敌人数量按开局队伍人数配置并锁定，不能由 DM 因骰子结果临时改动。

## 4. 核心循环与多人节奏

大厅：创建房间 → 选择模式 → 取名并选择预设角色 → 邀请朋友 → 房主开始。加入上限在数据库事务内强制为 6；重连恢复原席位，不能重复占位。

探索：所有人可讨论；行动提交由服务端串行处理并带 action_id 去重。每人至多一个待处理行动，AI 忙时显示队列。关键场景移动由房主触发，避免一个玩家连点将其他人拖过剧情。首版不需要复杂全员投票。

战斗：先攻队列由脚本生成；只有当前角色可以执行战斗动作。玩家可提前输入讨论内容，但不能抢回合。没有自动倒计时惩罚；房主可暂停，断线保持角色与回合。跳过离线玩家必须是房主显式操作并记入事件。

结束：服务器保存状态和时间线，提供继续房间和导出记录。DM 摘要是方便阅读的派生信息，不是恢复世界状态的依据。

## 5. 规则边界

规则固定为 SRD 5.1，不能混入 2024/5.2 变化。能力调整值、熟练加值、d20 检定、优势/劣势、命中、伤害、生命、先攻由 Python 计算。攻击自然 1/20 与一般检定区别处理；暴击加倍伤害骰而非固定加值。

首版建议实现：六项属性、服务器预设角色、属性/技能检定、豁免、普通武器攻击、先攻回合、预注册治疗、战斗结束、资源消耗。必须注明暂未支持完整职业成长、全法术、机会攻击、掩护与网格距离、完整状态系统、复杂多目标反应链。

角色以明确标注的简化预设原型提供，不用“法师”名义暗示完整法术表。选取战士、斥候、学者、侍者等叙事定位；规则能力仅显示已实现的部分。若实现法术则逐个注册成本、目标、骰式、效果，LLM 只能引用 spell_id。

未支持动作返回“此动作尚未自动裁定”，可转为叙事讨论；不得偷偷让 LLM 自行判定成功。自定义 DC 是冒险设计参数，预设模式取脚本常量；生成模式只能取合法离散等级并在掷骰前锁定。

## 6. DM 协议

输入：公开场景、角色状态、已确认事实、最近有限事件、玩家意图，以及已结算规则结果。隐藏剧情只传给 DM，不出现在玩家快照。

输出：短叙事、NPC 台词、至多三个行动建议；所有建议引用服务器 action_id。模型不能返回能直接写入状态的任意补丁。叙述里的未经结算数值不能成为事实，结果卡永远优先于文字。

单次回应建议 80–180 汉字，给玩家留表达空间；不代替玩家说话或决定动机。失败增加压力、代价或新路径，不重复要求同一骰子。遇到模型超时保留已结算结果，允许重试叙事，不重新掷骰。

## 7. 房主与现代在线体验

- 房主控制：开始、暂停、继续、结束会话；重要操作鉴权且写审计日志。
- 邀请链接只承载房间入口，个人会话令牌单独保存；离开房间与退出登录区分。
- 默认不公开模型密钥；由部署环境设置模型端点、名称、超时、Key；房主界面只显示启用状态。
- 公共时间线区分玩家发言、DM 叙事、规则结果和系统通知。骰子卡显示原始骰面、加值、目标、最终结果。
- 可恢复网络状态、提交失败重试、明确“DM 正在回应”、可减少动画、键盘操作与手机单栏布局。
- 开局声明题材与边界；暂停入口始终可见。第一版不默认引入玩家对抗和强制 PvP。

## 8. 验收场景

1. 六个独立会话入席，第七位被拒绝；重连不增加人数。
2. 同一 action_id 重发不重复扣费或掷骰；过期版本提交不污染状态。
3. 模型输出“造成 999 点伤害”不改变服务端 HP。
4. 无 Key 完成预设冒险；有 Key 可生成通过校验的另一份冒险。
5. 战斗非当前玩家行动被拒绝；战斗结束后回到探索。
6. 停服重启后使用恢复凭证可回到同一房间；错误凭证不能查看私有状态。
