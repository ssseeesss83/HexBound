# 角色创建与冒险起始等级

HexBound 的职业、法术与升级资料采用 2014 / SRD 5.1。角色创建中的自定义基础属性属于本游戏房规；文字背景与天赋不授予规则能力。

## 起始等级由冒险决定

剧情本的 `starting_level` 为 1–20 的整数，默认 3。创作者在工坊填写、预览、校验并发布后，新建房间冻结该剧情本及其依赖版本。修改草稿不会影响发布版本；重新发布也不会改变已经创建的房间。

公开剧情摘要包含起始等级，完整剧情节点仍不公开。旧剧情包缺少该字段时，新建房间按 3 级处理，不修改原内容包；已经存在且没有起始等级字段的旧房间仍按 1 级兼容，不追溯升级现有角色。

## 自定义角色

玩家选择职业、名字与六项基础属性：力量、敏捷、体质、智力、感知、魅力。每项必须是 8–20 的整数。此方式不使用标准数组或购点预算，因此可能比标准角色更强；房间参与者应按共同约定分配属性。服务端仍负责属性修正、生命、熟练加值、法术资源等派生数值，客户端不能指定生命、经验、资源或直接指定最终等级。

外貌、性格、背景分别最多 3000 字符。叙事天赋最多 20 项，每项最多 300 字符，可以描述“能听懂古老钟声”等故事设定，但不会自动增加属性、熟练、法术、伤害、抗性或额外动作。LLM 可以使用这些信息讲述故事，不能据此绕过规则脚本。

## 从 1 级逐级完成选择

高等级角色也先建立 1 级职业基础，再依次应用每一级的选择，直到房间起始等级。每一步先预览：补齐该级要求的技能、专精、子职业、属性值提升、戏法、已知法术、准备法术、法术书或已实现的职业法术选择，再进入下一级。职业和等级决定可选项及数量；最终提交时服务端重放整个构建过程，不信任客户端预览数值。

准备法术、已知法术等列表提交该级的完整目标列表，而不是只提交新增名称。最终构建必须恰好包含“目标等级减一”次升级步骤，不能跳级或省略必需选择。进入冒险后的经验升级仍使用同一套职业校验和逐级流程，不能通过更换剧情摘要提高已有角色等级。

当前支持的正式选择包括已实现的 SRD 子职业、属性值提升、技能与专精、法术以及已实现的职业法术选择。通用专长、战斗风格和魔能祈唤尚无完整选择系统；资料库中存在某项特性不等于该特性已经自动执行。以界面可选项和自动化状态为准。

## 构建数据约定

角色构建请求包括 `class_id`、`name`、`abilities`、`profile`、1 级的 `choices`，以及 `levels: [{choices: {...}}, ...]`。`abilities` 使用 `str/dex/con/int/wis/cha`；`profile` 使用 `appearance/personality/background/talents`。目标等级由房间决定，服务端拒绝越权数值字段。具体接口以 API schema 为准。
