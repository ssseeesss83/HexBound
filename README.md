# HEXBOUND · 缚骰

**命运有据，故事无界。** 最多六位玩家共享一张在线冒险桌：LLM 扮演 DM，Python 执行掷骰、角色成长、战斗与资源规则。

**v0.6** 提供账号绑定的持久角色、2014 / SRD 5.1 十二职业与 1–20 级成长、完整人物卡、独立战斗界面、受约束的 DM 自由行动提案，以及技能／怪兽／剧情本内容工坊。午夜航海日志风格的中文 Web 界面无需构建即可运行。

本项目实现可玩的规则核心和明确登记的能力；**319 项法术资料可查，不等于 319 项法术全部自动执行**。未实现效果会标为规则参考，不能让语言模型伪造结算。

## 立即开始

```sh
git clone https://github.com/ssseeesss83/HexBound.git
cd HexBound
cp .env.example .env
# 按 .env.example 设置初始管理员及可选的模型参数
docker compose up -d --build
```

1. 打开 **http://localhost:8000/account.html**，注册或登录。
2. 回到首页，从 **我的角色** 自定义属性、外貌、背景、初始技能与法术；可让 AI 补全草稿，逐项审阅后保存。
3. **创建冒险**，选择内容来源、互动方式、已有角色或模板，以及起始等级（默认 3 级，支持 1–20 级）；所有玩家逐级确认起始构筑后开团。向同伴发送邀请码。朋友应访问同一台服务器，各自的 `localhost` 不是同一张桌。
4. 房主开始后，使用场景行动、文字交流或 **向 DM 提出行动** 推进；有遭遇时进入战斗视图。
5. 点击自己的 **完整人物卡** 管理能力、法术、休息与升级。完成冒险后，角色可带入下一场游戏。

没有模型 Key 也能体验原创预设冒险及本地演示主持；即时自由生成需要可用的 LLM。Python 直接启动、HTTPS、备份与反向代理见 [部署说明](docs/deployment.md)。本项目包含后端和数据库，不能仅靠 GitHub Pages 运行。

## 角色与成长

| 内容 | 当前实现 |
| --- | --- |
| 十二核心职业 | 野蛮人、吟游诗人、牧师、德鲁伊、战士、武僧、圣武士、游侠、游荡者、术士、邪术师、法师 |
| 人物卡 | 六项属性、18 项技能与六项豁免、熟练／专精、HP、护甲、装备武器、生命骰、职业资源、法术位与职业特性 |
| 1–20 级成长 | XP 或场景里程碑资格、逐级预览、子职业、属性提升、法术与专精选择；固定平均 HP，体质提升回溯历史生命 |
| 法术管理 | 戏法、已知／准备法术、法师法术书、仪式资格、邪术师契约位、魔法奥秘与玄奥秘法的成长选择 |
| 持久人物库 | 账号拥有角色，存档跨设备恢复；同一人物同时只有一个有效冒险状态，避免多房间复制资源 |
| 休息与奖励 | 短休可花生命骰并恢复对应资源；长休恢复生命和对应资源，受游戏时间限制；奖励由脚本和去重记录发放 |

职业模板提供标准数组；新建角可按明确房规自定义六属性（每项 8–20），并手选初始技能、法术和逐级成长。AI 只提供可编辑草稿，不能直接授予数值或跳过升级。自定义叙事天赋不产生机械效果。当前没有完整的种族、背景、专长、多职业和所有职业细分选项构建器；不额外赠送未实现的种族／背景收益。SRD 仅开放每职业一个子职业，不能代表所有商业扩展子职业。

建角与起始等级见 [角色创建说明](docs/character-creation.md)，其他操作与规则限制见 [核心玩法说明](docs/core-gameplay.md)。

## 战斗与自动化能力

先攻、动作／附赠动作、武器攻击、额外攻击、命中、暴击、伤害、治疗、资源消耗与死亡豁免由脚本执行。普通属性检定不会把自然 1/20 视为自动失败／成功。攻击自然 1/20、优势／劣势抵消及暴击伤害骰分别处理。

日志增量更新并保留展开的骰子详情；位于底部时自动跟随新记录，上翻阅读时保留位置并显示“跳到最新”。

战斗视图显示队伍、先攻顺序、敌方生命、目标选择、行动分类、法术位、资源余额和规则凭据。行动菜单来自角色实际拥有的能力；没有学会的法术和未装备的剧情技能不会因目录里存在就变成可用行动。

当前 `abilities.SPELL_EFFECTS` 登记 **32 项法术效果**，包括魔法飞弹、火焰箭、魔能爆、神圣火焰、灼热射线、火球术、闪电束、治疗伤口、治愈真言、祝福术、信仰之盾等。部分空间或附加效果采用明确的辅助裁定：详情区分 `automated`、`assisted` 和 `reference`，实时标记比静态数量更准确。复杂召唤、许愿、高价材料消耗等不支持时直接拒绝执行。

职业处理器覆盖回气、动作如潮、狂暴、诗人激励、圣疗、神圣惩击、疾风连击、闪身防御、奥术回想、灵活施法等核心能力。其余特性保留完整规则说明及未自动化标记。**完整成长表和特性目录不等于所有职业特性全自动。**

## 内容来源与互动方式

| 维度 | 选项 | 行为 |
| --- | --- | --- |
| 内容来源 | 预设剧本 | 原创短篇或工坊发布的节点分支剧情 |
| 内容来源 | 自由生成 | 模型按主题生成受结构和规则约束的冒险；不是无限开放世界 |
| 内容来源 | 混合模式 | 保留作者主线和规则，由模型丰富叙事 |
| 互动方式 | 剧本引导 | 通过当前合法行动推进 |
| 互动方式 | 自由创作 | 自由描述；房主可修改当前叙事，数值与路由仍由规则执行 |
| 互动方式 | LLM 引导 | 模型回应并给出待确认的合法行动建议 |

新的 **DM 行动提案** 可以把自由描述整理为对话、18 技能检定或允许的遭遇提案。玩家确认后，服务端读取自己的提案快照，计算修正、DC 与结果；客户端只提交提案 ID。旧提案、非法目标、越过主线权限或模型编造的数字不能直接修改世界。模型不能凭一句文字提升角色等级、授予任意能力或修改生命。

## 技能行动与自由行动 · v0.5

探索和战斗均可切换 **技能行动／自由行动**。技能行动使用人物已有能力；自由行动输入意图，由 DM 选择服务器注册的规则方案。提案展示目标、物件、检定、效果和动作／移动代价，确认后才掷骰并执行；失败也消耗规定资源，取消不消耗，状态变化后须重新裁定。

当前支持18种行为：推倒、推离、擒抱、挣脱、协助攻击、临时武器攻击、扬沙、推翻障碍物、搭建掩体、点燃、灭火、操作物件、接近、撤远、起身、疾走、隐蔽、搜索。它们与技能共享动作额度，不能靠自由描述绕过回合或资源限制。启用LLM时，结算后仅根据已确认事件补充叙事；未配置LLM可识别部分明确意图并使用本地规则提案。

环境物件由工坊作者或结构化冒险生成定义，保存燃烧、损坏、倒塌、已搜索等状态。点火需要已有火源；没有登记的物体不会仅凭一句话生成。旧冒险没有物件时保留原状态，新建内置冒险包含可互动对象。

采用明确的抽象战场房规：默认30尺移动、接近或撤远消耗15尺，无网格或机会攻击。复杂自由计划需分步执行；尚无处理器的行为会说明限制，不能假称已完成任意物理效果。环境编辑与规则边界见 [自由行动作者说明](docs/free-actions-authoring.md)，独立验收见 [评审记录](docs/free-action-review.md)。

## 内容工坊

首页 **内容工坊**（`/studio.html`）供创作者和管理员管理：

- **技能卡**：攻击、治疗、检定、防御四类已注册效果，配置合法目标、骰式与使用次数；检定卡可关联18技能，按人物熟练／专精结算。
- **怪兽卡**：生命、护甲、先攻、攻击数据与击败XP；遭遇支持多个独立敌人。
- **剧情本**：节点、成功／失败分支、遭遇和结局；内置七节点双结局版《雾港最后一盏灯》。
- **管理闭环**：搜索、草稿、复制、校验、发布、归档、版本历史、恢复、依赖内容包导入导出、LLM 草稿辅助。

开团冻结已发布内容的版本。后续编辑不改变当前冒险；引用缺失、不可达节点或没有出口等问题会阻止发布。剧情技能属于受约束的自定义卡片系统，并不自动等同于官方职业能力。玩家只使用分配／装备给自己的卡片，重新装备不恢复次数。

扩展效果需增加 Schema、服务端处理器、目标校验和测试，不能只添加表单选项；不执行上传的 Python 或模型生成代码。详见 [扩展契约](docs/extensibility.md)。

## 账号与部署

首次启动前设置 `HEXBOUND_BOOTSTRAP_ADMIN_USERNAME` 与 `HEXBOUND_BOOTSTRAP_ADMIN_PASSWORD`。没有默认密码；初始化成功后可移除该密码。`/account.html` 提供账号管理，管理员可管理角色权限、启停账号、重置密码及查看审计。权限变更和禁用撤销会话，最后一个有效管理员受到保护。

席位绑定账号，跨设备登录可恢复。旧匿名席位须持原凭证一次性认领；绑定后不能靠旧 Bearer 绕过账号认证。游客模式与共享管理密钥默认关闭。HTTPS 部署设置 `HEXBOUND_COOKIE_SECURE=1`。详见 [账号与权限](docs/accounts.md)。

模型使用 OpenAI-compatible `/chat/completions`，通过服务端 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 配置。密钥不发送到浏览器。超时和格式错误不会重掷已提交骰点；失败的自由剧本生成可在大厅重试。

**当前部署必须是单 worker、单实例。** SQLite 保存账号、房间、角色、事件、内容版本和命令回执。多副本部署需要额外的房间所有权、协调机制与数据库设计。此版本面向小型自托管私团，不宣称已具备商业多租户平台的全部运维能力。

## 仍然明确的边界

- 没有战术网格、完整距离／掩护、机会攻击和完整反应链。范围法术采用明确选择目标的抽象遭遇规则，不能冒充精确战场模拟。
- 没有全法术、全职业特性自动化；目录中的复杂效果仍需主持人裁定。
- 倒地者点击结束回合进行死亡豁免；自然 20 恢复 1HP 后该轮结束。战胜遭遇后自动稳定存活倒地队友。这两项是当前公开房规。
- 现代人物使用生命骰与短长休资源规则；旧演示关卡遗留的简化机制以当前行动菜单和规则说明为准，不能将其误称为完整 SRD。
- 工坊是共享内容库，尚无逐条内容所有权、审批协作或多人编辑合并；没有语音、PvP 和商业扩展内容。

## 开发与验证

```sh
pip install -r requirements-dev.txt
python -m pytest -q
node --check frontend/app.js
npm ci
npm run test:ui
npm run test:studio
npm run test:accounts
npm run test:rooms
npm run test:combat
npm run test:free-action
```

Python 测试覆盖规则、成长、施法、持久化、账号与多人一致性；DOM 冒烟测试通过实际 HTTP/WebSocket 验证关键流程，不能替代真实浏览器的视觉验收。
