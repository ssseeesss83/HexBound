# HEXBOUND · 缚骰

**命运有据，故事无界。** 一张最多容纳六位冒险者的在线游戏桌：AI 讲故事，Python 执行规则，所有人共享同一份冒险记录。

原创短篇 **《雾港最后一盏灯》**，午夜航海日志风格的中文 Web 界面，1–6 名玩家 + AI DM。首版是可自托管的 5e SRD 5.1 核心规则子集，不是完整 D&D 模拟器。

## 开始游戏

```sh
git clone https://github.com/ssseeesss83/HexBound.git
cd HexBound
cp .env.example .env
docker compose up -d --build
```

打开 **http://localhost:8000** → 创建冒险 → 选择角色 → 把邀请码发给朋友 → 房主开始。没有模型 Key 也能体验预设冒险的本地演示主持。朋友需要访问同一台服务器；各自的 localhost 不是同一游戏桌。

Python 直接启动、模型参数、HTTPS、存档与备份见 [部署说明](docs/deployment.md)。本项目包含 Python 后端，不能仅靠 GitHub Pages 运行。

## 玩法与模型

- **预设冒险**：原创五场景主线、线索、调查、交涉、武器战斗与结局。
- **自由生成**：配置模型后，按主题生成四幕探索与一个结局，包含原创场景、目标与检定行动；能力和 DC 受白名单校验。生成结果一次保存，后续使用同一套剧本。当前沿用固定推进骨架，并非无限开放世界。
- **混合模式**：预设主线与规则保持稳定，模型丰富场景和角色扮演。
- **共同游玩**：邀请码入席、房主开始/暂停/恢复、独立角色控制、实时同步、聊天和行动日志。
- **可追溯骰点**：显示原始骰面、属性修正、目标值、命中与伤害。服务端安全随机生成；没有声称实现密码学可验证的公平掷骰协议。
- **持久化**：SQLite 保存房间、角色、事件与命令回执，刷新重连与服务重启保留进度。

模型使用 OpenAI-compatible `/chat/completions`，配置 `.env` 的 `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL`。Key 仅用于服务端。模型故障不会让骰子重掷，也不会获得修改 HP、伤害或回合的权限。

自由模式未配置模型时不可创建；生成失败时房间保留在大厅，可以重试。混合模式和角色扮演在模型超时或返回格式错误时降级为本地回应。角色扮演可提供白名单内的行动建议，玩家点击后才由规则引擎执行，不因一句自由文本自动扣血或推进场景。

## 规则范围

已实现基础属性修正、d20 检定、优势/劣势与抵消、自然 1/20 的攻击规则、暴击双倍伤害骰、先攻、回合行动限制、武器攻击、药水治疗、倒地与死亡豁免。普通属性检定不会将自然 1/20 当作自动失败/成功。

预设人物是固定的简化一级原型，并非完整职业卡。暂不支持职业升级、完整法术与职业特性、网格距离、机会攻击、完整状态与反应链、PvP、语音或战术地图。未注册的行为只能讨论，不能让模型假装完成裁定。

**公开房规**：每次短篇一次全队完全休整；战斗胜利后稳定仍存活的倒地队友；怪物按开局队伍规模使用简化遭遇模板；倒地角色点击结束回合触发死亡豁免，自然 20 恢复 1HP 但本轮不再行动。以上是本项目的短篇适配，不是完整 SRD 休息、稳定、遭遇或死亡豁免时序。房主的场景推进属于队伍管理，只要还有清醒同伴，房主角色倒下也不会锁死进度。

## 开发与验证

```sh
pip install -r requirements-dev.txt
python -m pytest -q
node --check frontend/app.js
npm ci
npm run test:ui
```

`test:ui` 自动启动独立临时数据库的服务器，通过 DOM 与实际 HTTP/WebSocket 验证六个玩家、满员拒绝、开局、共享骰点、聊天与暂停恢复；它不替代浏览器视觉布局验收。

必须使用 **单 worker、单实例**；不要直接扩为多副本。该版面向小型自托管私团，尚不是开放公网的多租户商业平台。浏览器本地保存恢复凭证，关闭标签页后可从首页“继续冒险”恢复；邀请码只用于新玩家入席，开局后不接纳新角色。不要清除此站点的本地存储。

规则归属与改编说明见 [NOTICE.md](NOTICE.md)。故事、界面和规则实现不依赖未授权的商业冒险内容或插图。
